# Loaf Chat on Windows — Implementation Plan (outline)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Status:** outline. Decisions, architecture, file map, task boundaries and Review Focus are settled. Step-level test and implementation code still has to be written into each task before it runs, following writing-plans: no placeholders.

**Goal:** Loaf Chat builds, runs, plays media and updates itself on Windows x64. It ships unsigned, as a per-user Inno Setup installer that updates itself from the same signed `latest.json` the AppImage uses.

**Architecture:** This plan covers all three pieces from `2026-09-29-desktop-updates-design.md`: bring-up, media, and the updater.
- **The app:** the Flutter Win32 runner hosts it.
- **Video:** Windows' own streaming hook. A custom `IMFByteStream` is handed to `IMFMediaEngine::SetSourceFromByteStream`, and reads the growing `.part` through the same wait-for-bytes logic as Linux's `loafsrc`, moved into a crate both platforms share. Frames reach a Flutter `GpuSurfaceTexture` as a DXGI shared handle. Controls are drawn in Flutter, reusing Linux's widget, since Flutter on Windows has no platform views.
- **Images:** they open in the existing Flutter viewer. Where Flutter's codecs refuse a format (HEIC, AVIF), WIC decodes it.
- **Updates:** they work like the AppImage. The app reads `latest.json` and downloads a zip of the bundle. It checks the zip's ed25519 signature and SHA-256, unpacks it beside the install, swaps the files in, and restarts. Inno Setup does only the first install, the Start menu entry and the uninstall entry.

**Tech Stack:**
- Flutter 3.47.5 and Rust 1.96.1 (both pinned in `mise.toml`).
- The `windows` crate (windows-rs) for Media Foundation's Media Engine, D3D11 and WIC; a thin C++ Flutter plugin.
- Inno Setup 6 for the installer.
- GitHub Actions on `windows-latest`.

**Spec:** none yet. The decisions below were made with Chris on 2026-10-05/06 and amend `2026-09-30-media-design.md` and `2026-09-29-desktop-updates-design.md`. Task 0 writes them up as `docs/superpowers/specs/2026-10-05-windows-design.md`.

## Decisions (2026-10-05/06)

| Question | Answer |
|---|---|
| Packaging | A per-user Inno Setup installer. No MSIX, no Microsoft Store |
| Signing | None. SmartScreen and Smart App Control are documented in the README. SignPath can sign the same files later without changing anything else |
| Updates | Our own, AppImage-style: `latest.json` gains a `windows` asset, signed with the same release key |
| Where Windows is tested | CI only (`windows-latest`); no manual Windows box |
| Opening an image | The in-app `ImageViewer`, as on Linux; "Open in <default app>" in the menu |
| HEIC/AVIF | A WIC decoder fallback |
| Video player language | Rust (windows-rs) plus a thin C++ plugin, mirroring Linux |

## Global Constraints

- **Platform:** Windows 10 1809+ x64 only. arm64 is deferred.
- **Native first:** each Windows behaviour uses the Windows mechanism meant for it. The two portable pieces exist because Windows has nothing native for them without signing or a system sign-in window:
  - the loopback SSO, already in `lib/matrix/sso_browser.dart`;
  - our own updater.
- **Rust:** no `.unwrap()`, and every `extern "C"` function catches panics. Return codes match `loaf_media_rs.h`: 0 OK, -1 panic, -2 bad string, -3 failed, -4 null pointer.
- **Media channel:** stays `moe.loaf.chat/media`, with the same `stream.*` and `video.*` contract as Linux.
- **Build numbers:** the commit count on `main`, as everywhere. Every updater compares build numbers, so they only go up.
- **Install location:** per user, at `{localappdata}\Programs\Loaf Chat`. Nothing asks for admin, ever, so the updater can always write its own folder.
- **What the release key signs:** each asset's own text, prefixed with its kind. The AppImage's stays `loaf-chat-appimage\n…`, and Windows uses `loaf-chat-windows\n…`, so a signature for one can never pass for the other.
- **Release testing:** merge, tag, and watch it in CI (memory: release-test-via-ci).
- **Naming:** "Loaf Chat" wherever Windows shows a name.

## Review Focus

1. **A video plays while its `.part` is renamed or evicted.** Dart renames `.part` to `<name>` while the Media Engine still holds a reader. Windows refuses the rename unless every handle shares delete. → Task 3 (Rust test: open, rename from another handle, keep reading) and Task 2 (a Dart rename test on Windows CI).
2. **A sender's file name Windows refuses**, such as `CON.mp4`, `nul`, `photo.jpg.`, or a trailing space. A path over 260 characters fails in ShellExecute and Media Foundation even where Dart copes. → Task 2.
3. **An iPhone HEVC video without the HEVC Video Extension.** The row must show "couldn't play this · open it instead", never a black box. → Task 4 (codec errors set the player's error flag) and Task 5 (widget test).
4. **An update swap that fails halfway.** Defender holds a file it is scanning, or the disk fills mid-unpack. The install must end up whole: all old files or all new, and the app must still launch. A half-swapped install is a dead end the tester can't recover from without reinstalling. → Task 7: a journalled swap with rollback, tested by failing each rename in turn.
5. **Signing out mid-playback.** `VideoStreams.endAll` must wake every blocked `IMFByteStream` read with an error. It must never hang the Media Engine's work queue, and `video.dispose` after that must not crash. → Task 3 (threaded Rust test) and Task 4.

## File map

**Bring-up**
- `windows/`: create with `flutter create --platforms=windows .`. Then edit:
  - `windows/runner/main.cpp`: title "Loaf Chat", minimum window size;
  - `Runner.rc`: product name, icon;
  - `runner.exe.manifest`: `longPathAware`, per-monitor DPI v2.

**Shared streams crate**
- `packages/loaf_media/rust/loaf_streams/`: create. It's `linux/rust/src/streams.rs` moved out. Positional reads are platform-specific: `read_at` on unix, `seek_read` on Windows.
- `packages/loaf_media/linux/rust/Cargo.toml` and `src/lib.rs`: modify to depend on `loaf_streams`.

**Windows Rust crate** (`packages/loaf_media/windows/rust/`, `loaf_media_win`, a staticlib), all created:
- `byte_stream.rs`: `#[implement(IMFByteStream, IMFAttributes)]` over `loaf_streams`. `BeginRead` runs the blocking read on an MF work queue (`MFPutWorkItem2`).
- `player.rs`: `IMFMediaEngine` in frame-server mode on a D3D11 video device. A render thread calls `OnVideoStreamTick`, then `TransferVideoFrame` into one of two shared BGRA textures.
- `shell.rs`:
  - `openWithDefaultApp` through `ShellExecuteExW`;
  - `defaultAppName` through `AssocQueryStringW` with `ASSOCSTR_FRIENDLYAPPNAME`.
- `wic.rs`: decodes bytes to BGRA with WIC.
- `ffi.rs`, with the header at `windows/include/loaf_media/loaf_media_win.h`.

**Windows plugin**, created:
- `packages/loaf_media/windows/CMakeLists.txt`: builds the crate with cargo and links `mfplat`, `mf`, `d3d11`, `dxgi`, `windowscodecs` and `shlwapi`.
- `packages/loaf_media/windows/loaf_media_plugin.cpp`: the channel, one `GpuSurfaceTexture` per player, and the frame-available marks.

**loaf_media Dart**
- `packages/loaf_media/pubspec.yaml`: add `windows: pluginClass: LoafMediaPluginCApi`.
- `lib/src/linux_video.dart`: rename to `texture_video.dart` (`TextureVideo`).
- `lib/src/video.dart`: `supported`, `drawsOwnControls`, the platform switch.
- `lib/src/native.dart`: Windows doc lines, `decodeImage`.

**App media**
- `lib/ui/channel/wic_image.dart`: create. An `ImageProvider` that falls back to `LoafMedia.decodeImage` on Windows.
- `lib/ui/channel/media_open.dart`, `media_row.dart` and `message_actions.dart`: Windows cases.
- `lib/matrix/media_store.dart`: `safeName` and the path cap.

**Updater**
- `lib/update/release_feed.dart`: `AppImageAsset` becomes `ReleaseAsset`. `Release` gains `windows`, and `signedText` becomes `signedTextFor(AssetKind)`.
- `lib/update/windows_updater.dart`: create. A `StateUpdater` with the same shape and rules as `AppImageUpdater`.
- `lib/update/bundle_swap.dart`: create. The journalled file swap, pure Dart, testable on any OS.
- `lib/update/pick_updater.dart`: `UpdaterKind.windows`.

**Release**
- `windows/packaging/loaf-chat.iss`: the Inno Setup script.
- `tool/release/windows.sh`: run under Git Bash on the runner.
- `.github/workflows/release.yml`: a `windows` job, and `publish` merges its feed fragment.
- `.github/workflows/windows-check.yml`: `flutter test` and `cargo test` on `windows-latest`.
- `tool/release/site.sh` and `README.md`: the Windows download.

## Tasks

### Task 0: Spike — verify the risky findings on the CI runner

Throwaway branch and workflow. Write each finding into the spec:

- **The build:** `flutter create --platforms=windows` builds with the current pubspec on 3.47.5. That means flutter_vodozemac through cargokit with MSVC Rust, and sqlite3 3.x through its build hooks.
- **The video texture:** check whether `GpuSurfaceTexture` with `kFlutterDesktopGpuSurfaceTypeDxgiSharedHandle` draws under the renderer 3.47.5 uses on Windows (ANGLE or Impeller). If it doesn't, the fallback is `PixelBufferTexture` fed by a CPU readback, and the spec says so.
- **The swap trick:** a running `.exe`, and the DLLs it has loaded, can be renamed on the runner's NTFS. Then a new file can take the old name, and the process keeps running.
- **Inno Setup:** `iscc` (Inno Setup 6) is on the `windows-latest` image. If it isn't, install it from a pinned installer checked against its SHA-256, the way `appimage.sh` pins its tools.
- **Unpacking:** `tar.exe` (bsdtar, in Windows since 1803) unpacks a zip, so the updater needs no archive package.

Commit the spec. Chris reviews it before Task 1.

### Task 7: The Windows updater

**Feed.** `latest.json` gains:

```json
"windows": {"url": "…", "sha256": "…", "size": 0, "signature": "…"}
```

The signed text is `loaf-chat-windows\n<version>\n<build>\n<sha256>`, with no trailing newline. `Release.parse` keeps accepting feeds without the `windows` field.

Tests in `updater_test.dart`:
- an AppImage signature doesn't verify as a Windows one, and the reverse;
- an old feed with no `windows` field parses.

**`BundleSwap`** (`lib/update/bundle_swap.dart`), over an injectable file-system seam so every failure can be forced in a test:

- `stage(zip, stagingDir)`:
  - unpacks with `tar -xf`;
  - refuses entries that escape the folder (`..`, absolute paths).
- `apply(installDir, stagingDir)`:
  - writes `update.journal` first;
  - renames each installed file to `<name>.old`, then moves each staged file in, retrying a held file for up to 2 s (Defender scans);
  - on any failure, plays the journal backwards and rethrows;
  - leaves the Inno files (`unins000.*`) alone.
- `cleanUp(installDir)`: runs at launch. It deletes `*.old`. If a journal is still there, a crash interrupted a swap: it finishes rolling back first.

Tests:
- fail the n-th rename for every n, and the install equals the old one each time;
- a crash mid-swap leaves a journal, and the next launch's clean-up restores the old install;
- a zip with `..\evil.dll` is refused.

**`WindowsUpdater extends StateUpdater`**, structured like `AppImageUpdater`:
- the same timers (30 s after launch, then hourly), size cap, idle timeout, signature check and hash check;
- download to `%TEMP%`, then `stage`, then `apply`, then `UpdateReady(version)`;
- `restart()` starts the exe detached and exits.

An update nobody restarts into is already in place, so it runs at the next launch.

**`chooseUpdater`** returns `UpdaterKind.windows` when `unins000.dat` sits beside the executable, meaning Setup installed it. A build run from `build\` gets none. The test "Windows has none yet" becomes "a Setup install gets windows, a loose build none".

### Task 8: Release

**`windows.sh`** in a `windows` job on `windows-latest`, with `shell: bash`:
- `flutter build windows --release` with the build name, the build number and `LOAF_BUILD`;
- zip the bundle as `Loaf-Chat-$version-windows-x64.zip`;
- sign it the way `appimage.sh` does, with `APPIMAGE_PRIVATE_KEY` held in an unexported variable and on disk only during `openssl pkeyutl`;
- write the `windows.json` fragment;
- `iscc` builds `Loaf-Chat-$version-Setup.exe`.

**`loaf-chat.iss`:**
- `PrivilegesRequired=lowest` and `DefaultDirName={localappdata}\Programs\Loaf Chat`;
- a Start menu shortcut and an `AppUserModelID`;
- `[UninstallDelete] filesandordirs {app}`, so files an update added since Setup ran also go.

**`publish`:**
- `needs: windows`;
- `jq` merges `windows.json` into `latest.json` before `pages.sh` runs;
- uploads the Setup exe and the zip before the release leaves draft, so the feed never names a file that isn't there.

**README:**
- download `Setup.exe`;
- SmartScreen: More info, then Run anyway;
- Smart App Control can block the app outright on some fresh Windows 11 installs;
- no admin prompt, ever.

Then merge, tag, and watch the run.

| Deferred | Why |
|---|---|

| Windows arm64 | x64 first |
