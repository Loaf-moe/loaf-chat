# Pinned Messages Implementation Plan

**Goal:** Messages can be pinned, read from the channel header, jumped to, and the conversation says who pinned what. Discord's shape.

**Architecture:** `Timeline` (`lib/ui/channel/timeline.dart`) carries the pins: `pinnedIds`, `canPin`, `pin`, `unpin`, `fetch`. `TimelineController` plays them locally; `MatrixTimeline` reads `Room.pinnedEventIds` and writes `Room.setPinnedEvents`, and maps `m.room.pinned_events` timeline events to a `Message.pinLine`. `PinnedPanel` (`lib/ui/channel/pinned_panel.dart`) is the list, opened from the header's pin button; `_PinLineTile` in `channel_view.dart` is the line.

**Tech Stack:** Flutter 3.47.5 (pinned in `mise.toml`; run every command through `mise exec --`), `matrix` 13.0.0. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-26-pins-design.md`. Read it first; the seam, the wording and the test cases are there and are not repeated here.

## Global Constraints

- `lib/ui/` does not import `package:matrix`.
- Tests use no network: the Matrix side runs against the `FakeMatrixApi` subclass in `test/matrix/matrix_timeline_test.dart`.
- Each test is written before the code it covers.
- No pin shows before the room's state says so; no confirmation asks; no cap.

## Task 1: pinned messages

Commit: `feat(pins): pinned messages`

**Files**

- `lib/ui/model/models.dart`: `PinLine`, `Message.pinLine`, `PinEntry`, and `groupTimeline` giving a pin line its own entry.
- `lib/ui/channel/timeline.dart`: the five new `Timeline` members.
- `lib/ui/channel/timeline_controller.dart`: pins at once, lands a pin line from you, fetches from what it has.
- `lib/ui/mock/mock_rooms.dart`, `lib/ui/mock/fixtures.dart`: the shared conversation starts with two pins and a pin line.
- `lib/ui/channel/message_actions.dart`: `MessageAction.pin` and `unpin`, gated in `actionsFor` on `canPin`, a sent, readable message that is no line.
- `lib/matrix/matrix_timeline.dart`: `pinnedIds`, `canPin`, `pin`, `unpin`, `fetch`; the pin-line mapping with `prevContent`; the first opening kept as `_ready` for `fetch` to wait on.
- `lib/matrix/client_factory.dart`: `EventTypes.RoomPinnedEvents` among `importantStateEvents` (see the spec's findings for why).
- New `lib/ui/channel/pinned_panel.dart`: `showPinnedPanel`, `PinnedPanel`.
- `lib/ui/channel/channel_view.dart`: the header's pin button, `_PinLineTile`, the `PinEntry` cases.
- `lib/ui/channel/message_group_tile.dart`: `formatMessageTime`, public, shared with the panel and the line.

**Tests that change on purpose**

- `test/channel_view_states_test.dart`, `test/channel_view_media_test.dart`, `test/channel_view_encryption_test.dart`: `_FakeTimeline` gains the new members; the first also records jumps and takes a channel.
- `test/matrix/matrix_timeline_test.dart`: `_Api` answers pinned-events puts and `/event/{id}`; `_sync` and `_open` take further room state.

**New tests** (the spec's Testing section lists the cases)

- `test/group_timeline_test.dart`, `test/timeline_controller_test.dart`, `test/message_actions_test.dart`, `test/matrix/matrix_timeline_test.dart`, `test/channel_view_states_test.dart`: a `pins` group each.
- `test/pinned_panel_test.dart`.

**Verification**

- `mise run check`
- `mise run test:all`
- `mise run build:linux`, then by hand on loaf.moe:
  - pin from the menu as a moderator, and the line lands;
  - the list from the header, with a pin from far back in history that fetches;
  - a jump from the list and from the line;
  - unpin from the list;
  - a plain member sees no Pin;
  - an encrypted room from an unverified device pins;
  - whether tuwunel sends `prev_content` for pinned events over `/messages`, which decides what old lines say.

## Deferred

A mark on a pinned row, a line on unpin, confirming a pin or unpin, a cap, showing a pin before the server answers, edits of a pinned message that is not loaded, pins outside the open conversation, searching the list.
