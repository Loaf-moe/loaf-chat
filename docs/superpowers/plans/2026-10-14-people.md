# People Implementation Plan

**Goal:** Every drawn name is one widget, with a Discord badge for bridge puppets; every name and avatar opens one person menu with their card on top; a tap on a timeline name mentions them; someone can be taken out of a call and left in the channel.

**Architecture:** The adapter sets `Member.bridge` from the user id, and the UI reads the enum alone. `PersonName` and `showPersonMenu` are the two UI seams; every place that draws a person goes through them. Mentioning from outside the composer rides `Timeline`, as reply and edit targets do. Removal from a call rides `moe.loaf.call.moderation`, as muting does.

**Tech Stack:** Flutter 3.47.5 (pinned in `mise.toml`; run every command through `mise exec --`), `matrix` 13.0.0. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-14-people-design.md`. Read it first; the findings, the menu's table and the copy are there and are not repeated here.

**Not rehearsed.** The tasks below were not run on a scratch copy first. Each is planned in detail when it starts.

## Global Constraints

- `lib/ui/` does not import `package:matrix`.
- Tests use no network: the Matrix side runs against a `FakeMatrixApi` subclass.
- Each test is written before the code it covers.
- The UI never branches on a user id. A puppet is `member.bridge != null`.
- Nothing in a menu asks for confirmation except "kick from space".
