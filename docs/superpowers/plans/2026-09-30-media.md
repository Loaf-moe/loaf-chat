# Images, Files and Video Implementation Plan (SDK phase 9)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Media sent to you arrives as media:
- pictures in the timeline;
- video playing in place, in each platform's real player, while it downloads;
- every file opening in the platform's own viewer, and savable;
- encrypted rooms working like plain ones;
- "didn't send" within about 30 s offline.

**Architecture:**
- **One new seam, `MediaSource`** (`lib/ui/model/media_source.dart`), handed out by `Rooms` like `avatarImages`. It turns a plain `Media` value into preview and full `ImageProvider`s and a `MediaFile` on disk. `MockMediaSource` serves bundled samples. `MatrixMediaSource` sits on a new `MediaStore`, which streams, decrypts as it goes, and caches.
- **One local Flutter plugin, `packages/loaf_media/`,** holds everything native:
  - shared Swift for iOS and macOS: Quick Look, the default app, and an `AVPlayer` view fed by an `AVAssetResourceLoaderDelegate`;
  - a Linux plugin: thin C glue over a Rust crate on GStreamer, with a `loafsrc` source element streaming the growing file into `playbin`.
- **`LoafHttpClient`** wraps the SDK's HTTP: a 20 s limit on waiting for headers, a 30 s idle limit on uploads, and upload progress.

**Tech Stack:**
- Flutter 3.47.5 via `mise exec -- flutter`.
- `matrix` 13.0.0, and `vodozemac` (`CryptoUtils.aesCtr`).
- Swift 6 with AVFoundation, AVKit and QuickLook, through Swift Package Manager (`sharedDarwinSource`).
- Rust 1.96.1 (pinned in `mise.toml`) with `gstreamer` / `gstreamer-base` / `gstreamer-app` / `gstreamer-video` 0.25.
- GStreamer ≥ 1.20 and C for the Flutter Linux embedder.
- New Dart dev dependency: `fake_async`.

Real-SDK tests run offline over a real `Client` on `FakeMatrixApi` with an in-memory database. ## Global Constraints

- **Native first** (memory `native-first`): each platform's own mechanism.
  - No local servers, no polling of files, and no "it already works over there" reuse in place of the API meant for the job.
  - If a step seems to need a workaround, stop and ask.

## Review Focus

1. **An encrypted file whose length isn't a multiple of 16, arriving in chunks that split AES blocks.** The decrypted bytes must equal the SDK's whole-file decrypt. Pinned in Task 3: "chunked decryption matches the whole-file decrypt at every boundary".
2. **Signing out while a video plays or a download runs.** Readers on both platforms wake with an error, nothing notifies after dispose, and `media/files/` is gone. Pinned in Task 3 ("disposing mid-download fails it and notifies nothing"), Task 6 ("a failed stream fails pending requests") and Task 7 ("fail wakes a blocked fill").
3. **The same file asked for twice** (a row's preview and the viewer, or two rows quoting one file). One download, both see it. Pinned in Task 3: "two opens share one download".
4. **An upload that stalls on a dead network.** The attempt aborts after 30 s idle, the message reads failed within about 30 s, and retry works. Pinned in Task 2 ("a stalled upload aborts after 30 s with no progress") and Task 4 ("a stalled upload fails the row").
5. **A media event with a broken or partial content block:** no `info`, no `size`, or a `file` map missing `key` or `iv`. Either a file card or "couldn't load · try again"; never a throw during mapping. Pinned in Task 4: "a media event missing its info maps to a file card" and "a broken file map fails the download, not the timeline".

  String get partialPath;

  bool get complete;

}

- [ ] **Step 1: Write the failing tests**

All of these run under `fakeAsync`, over a fake inner client that records requests and holds each response on a `Completer`. It completes with `RequestAbortedException` when the request's `abortTrigger` fires.
- "a request with no headers in 20 s is aborted".
- "headers in time are not aborted": complete at 19 s, then elapse 60 s, and the response still streams.
- "sync is never limited": `GET /_matrix/client/v3/sync?timeout=30000` held 120 s is not aborted.
- "an upload goes in 64 KB chunks and reports each": 200 KB of body gives progress `(65536, 204800)`, `(131072, …)`, `(196608, …)` and `(204800, …)` in order.
- "a stalled upload aborts after 30 s with no progress": the fake stops reading the body after 2 chunks. At 29 s it's still alive; at 31 s it's aborted.
- "a slow but moving upload is never cut off": one chunk every 25 s for 10 chunks, and it's not aborted.
- "uploads outside reportingUploads report nothing, and don't throw".
- "a body sent, then 20 s without headers, aborts": after the last chunk, the header limit applies.

`client_factory_test.dart`: "the client sends for 30 s before giving up". `openClient(...).sendTimelineEventTimeout == const Duration(seconds: 30)`.

```dart
@override
Future<http.StreamedResponse> send(http.BaseRequest request) async {
  // /sync long-polls for up to 30 s by design; the SDK's own body idle
  // limit covers it once headers arrive.
  if (request.url.path.endsWith('/sync')) return _inner.send(request);
  final upload = request.method == 'POST' &&
      request.url.path.contains('/media/') &&
      request.url.path.endsWith('/upload');
  final abort = Completer<void>();
  Timer? timer;
  void arm(Duration within) {
    timer?.cancel();
    timer = Timer(within, () {
      if (!abort.isCompleted) abort.complete();
    });
  }
  final progress = upload ? Zone.current[_progressKey] as UploadProgress? : null;
  final total = request.contentLength;
  var body = request.finalize();
  if (upload) {
    body = http.ByteStream(_chunked(body, (sent) {
      progress?.call(sent, total);
      arm(uploadIdle);
    }, onDone: () => arm(headersWithin)));
  }
  final copy = _Copy(request, body, abort.future);
  arm(upload ? uploadIdle : headersWithin);
  try {
    return await _inner.send(copy);
  } finally {
    timer?.cancel();
  }
}
```

- `_chunked` is an `async*` generator. It re-slices incoming lists into 64 KB views and `yield`s each one. Because it's paused at each `yield` until the socket takes the chunk, the counts follow what was actually sent.
- `_Copy extends http.BaseRequest with http.Abortable`. It copies `method`, `url`, `headers`, `contentLength`, `followRedirects`, `maxRedirects` and `persistentConnection`, and returns `body` from `finalize()`.
- In `openClient`:

**`CtrDecryptor`** keeps `_block` (the count of whole blocks done) and `_carry` (fewer than 16 bytes).
- `add` joins `_carry` and `chunk`, takes the largest multiple of 16, and decrypts it with `CryptoUtils.aesCtr(input: whole, key: key, iv: _ivAt(_block))`. It advances `_block` and keeps the rest as `_carry`.
- `_ivAt(n)` adds `n` to the IV as a 128-bit big-endian integer, carrying across all 16 bytes.
- `close` decrypts `_carry` at `_ivAt(_block)`.

**`MediaStore.open`** looks up `_running[spec.mxc]`, otherwise checks the finished file, otherwise starts a download.
- **`id`:** `sha256(mxc.toString())` in hex, from `package:crypto`.
- **Path:** `root/<id>/<safeName>`.
- **`_download`:**
  1. `await downloadUri(mxc)`.
  2. Send a streamed GET with `authorization: Bearer <token>`.
  3. A non-200 status throws.
  4. `total = response.contentLength ?? spec.size`.
  5. Open `<name>.part` with `FileMode.write`.
  6. For each chunk: decrypt (or pass through), `await raf.writeFrom(bytes)`, `received += bytes.length`, `notifyListeners()`.
  7. After `close()`, write the last block and `raf.close()`, then rename to `<name>`.
  8. Set `complete`, notify, and run `evict()` without awaiting it.

  - It's set on `AVURLAsset(url: URL(string: "loaf-media://\(id)")!)` with `asset.resourceLoader.setDelegate(loader, queue: stream.queue)`. Construct the URL with `URLComponents`, and fail with `FlutterError` if it's nil. Don't force-unwrap.
  - `shouldWaitForLoadingOfRequestedResource` stores the request and calls `serve()`, then returns true.
  - `didCancel` removes it.
- **`serve()`:** for each pending request:
  - **Content information:**
    - `contentType`: `UTType(mimeType: mime)?.identifier`, defaulting to `public.mpeg-4`;
    - `contentLength`: `total`, once known;
    - `isByteRangeAccessSupported`: true.
    - If `total` isn't known yet, leave the request pending.
  - **Data:** loop `nextStep(...)`:
    - `.respond`: `fileHandle.seek(toOffset:)`, `read(upToCount:)`, `dataRequest.respond(with:)`;
    - `.finish`: `finishLoading()`;
    - `.fail`: `finishLoading(with: NSError(domain: "moe.loaf.chat.media", code: 1))`;
    - `.wait`: leave it.
- **`VideoViewFactory`:**
  - **macOS:** an `AVPlayerView` with `controlsStyle = .inline` and `showsFullScreenToggleButton = true`.
  - **iOS:** a `FlutterPlatformView` whose `view()` is an `AVPlayerViewController.view`. The controller is added as a child of the root view controller, with `entersFullScreenWhenPlaybackBegins = false`, `allowsPictureInPicturePlayback = true` and `canStartPictureInPictureAutomaticallyFromInline = false`.
  - **Both:**
    - observe `player.timeControlStatus`; when it becomes `.playing`, send `video.playing {view}`;
    - `video.pause` calls `player.pause()`;
    - `dispose` pauses, removes the observer and drops the asset.
- **The plugin** registers the factory: `registrar.register(factory, withId: "moe.loaf.chat/video")`.

- [ ] **Step 2: Implement the Rust side**

**`streams.rs`:**
- `Registry` is a `OnceLock<Mutex<HashMap<String, Arc<Stream>>>>`.
- `Stream { state: Mutex<State>, cond: Condvar }`, where `State { path, received, total, complete, failed, ended }`.
- `Reader { stream: Arc<Stream>, file: File, flushing: bool }`.
- `Reader::read_at(offset, len) -> Result<Vec<u8>, ReadError>` locks the state and loops:
  - `failed` or `ended` → `Err(Failed)`;
  - `flushing` → `Err(Flushing)`;
  - `offset < received` → read `min(len, received - offset)` with `FileExt::read_at` and return it;
  - `complete && offset >= received` → `Err(Eos)`;
  - otherwise `cond.wait(state)`.
- `flushing` lives in `State` keyed by reader, or as one flag per source protected by the same mutex, so `unlock` can set it under the lock and `notify_all`.

**`source.rs`:** `LoafSrc` follows the `gst::subclass` pattern of the gstreamer-rs `basesrc` examples.
- `ObjectSubclass` named `"LoafSrc"`, parent `gst_base::BaseSrc`, interface `gst::URIHandler`.
- `URIHandlerImpl`: `protocols() == ["loaf-media"]`, `uri_type() == Src`. `set_uri` parses the id, which `start` looks up in the registry.
- `BaseSrcImpl`:
  - `is_seekable` → true;
  - `size` → `total`;
  - `fill(offset, length, buffer)` → `read_at`, then `buffer.map_writable()` and `copy_from_slice`, then `buffer.set_size(n)`. `Eos` → `Err(gst::FlowError::Eos)`, `Flushing` → `Err(Flushing)`, `Failed` → post an element error ("the download failed") and `Err(Error)`;
  - `unlock` and `unlock_stop` set and clear the flag and notify.
- `ElementImpl` metadata gives a src pad template with `ANY` caps.
- `register()` calls `gst::Element::register(None, "loafsrc", gst::Rank::PRIMARY, LoafSrc::static_type())`.

**`player.rs`:**
- `playbin` with `uri = loaf-media://<id>`.
- The video sink is an `appsink` with caps `video/x-raw,format=RGBA`, `max-buffers=1`, `drop=true`, `sync=true`.
- `new_sample` stores `(width, height, Vec<u8>)`, copying out of the mapped buffer, in `Mutex<Option<Frame>>` and calls `on_frame(user)`.
- A bus watch on a dedicated thread (`bus.iter_timed`) records `error` and `EOS`.
- `state` queries `query_position` and `query_duration`.

**`ffi.rs`:**
- Every `extern "C"` wraps its body in `catch_unwind(AssertUnwindSafe(|| …)).unwrap_or(-1)`.
- `CStr` → `&str` via `to_str()`; invalid UTF-8 returns -2.
- The player pointer is `Box::into_raw` and `Box::from_raw` in `free`.
- `loaf_rs_player_frame` keeps the borrowed frame in the player as `last_lent` until the next call.
