# Code audit — 2026-10-15

Scope: `lib/` (188 files, ~55k lines), `packages/loaf_media`, `packages/loaf_notify`,
`.github/workflows`, `mise.toml`, `tool/`. Chris's review notes (which stop at
`bundle_swap.dart`) are folded in and extended to the rest of the tree.

The lens: **make invalid states unrepresentable, let types construct themselves
from other types, and keep generic tools out of domain classes.** The codebase
already does this in a few places — `release_feed.dart` (pattern-matched parse
into a typed `Release`), `UpdateState`, `ServerCheck`, `LinkPreviewState`. Those
are the house style to copy. Most of the rest falls short of it.

## 0. Direct answers

### Snippet A (`AppImageUpdater` constructor)

```dart
AppImageUpdater({
  required this._appImage,          // (1)
  required this.build,              // (2)
  ...
  this.idleTimeout = const Duration(minutes: 2),   // (3)
  http.Client? httpClient,          // (4)
  Future<void> Function(String path)? launch,
  void Function()? quit,
}) : _http = httpClient ?? http.Client(),          // (5)
     _launch = launch ?? _launchDetached,
     _quit = quit ?? _exit;
```

1. **Private named initializing formal** (a recent Dart 3 addition). The field is `_appImage`,
   but the caller writes `appImage:` — Dart strips the underscore from the
   parameter name. It's the only way to have a private field set by a named
   parameter without an initializer-list line.
2. Plain initializing formal: assigns the public `final int build`.
3. Optional with a default; must be a compile-time constant.
4. Ordinary nullable parameters — *not* fields. They exist only so tests can
   inject a fake HTTP client, a fake launcher and a fake `exit`.
5. The **initializer list** (after `:`) runs before any constructor body and is
   the only place a `final` field can be assigned from a computed value. Each
   line says "use the injected thing, or the real one".

The smell: three nullable function parameters are a hand-rolled, untyped
dependency-injection container, copy-pasted verbatim into `WindowsUpdater`.
Replace with one typed collaborator (see §3.2).

### Where does `move` come from?

`StateUpdater.move` — [state_updater.dart:29](../lib/update/state_updater.dart).
It is **not** memory management. It sets `_state`, completes anyone waiting in
`settled()`, and calls `notifyListeners()`. The name is bad (Rust/C++ readers
will think ownership), and it accepts *any* transition — `Ready → Preparing` or
`Applying → Idle` compile fine. Rename to `transition`, and make the legal
transitions methods on the state types so an illegal one doesn't type-check.

### `_retrying` — "writes indefinitely"

It's bounded (`retryFor`, 2 s), but the `while (true)` + wall-clock check hides
that, and it lives inside `BundleSwap` though nothing about it is bundle-specific.
The *reason* for it is real (Defender briefly holds freshly written DLLs), so the
fix is shape, not deletion: a generic `retry(attempts: n, delay: d, on: FileSystemException)`
in a utilities module, called with an explicit attempt count.

### `_renameFile`

It exists because `File(from).rename(to)` returns `Future<File>`, and the
`FileRename` typedef wants `Future<void>`, so a tear-off doesn't fit as a default
parameter. That's the tail wagging the dog: the injection point is wrong. Inject a
`FileSystem` from `package:file` (already in the lockfile, transitively) and tests
use `MemoryFileSystem`; `_renameFile`, `FileRename` and the typedef all go.

## 2. App wiring — `main.dart`

**2.1 Backend is a string compared in four places.**
`backend == 'mock'` at lines 96, 101, 105, 115, and the mock/real split leaks
further (§5). Replace with one type that *produces* the right objects:

```dart
enum Backend { matrix, mock;
  static Backend fromEnvironment() => switch (const String.fromEnvironment('LOAF_BACKEND')) {
    'mock' => mock, _ => matrix };
}

sealed class AppServices {
  AppearanceStore get appearanceStore;
  NotificationStore get notificationStore;
  LoafSession get session;
  Rooms Function()? get rooms;
  Updater get updater;
  VoiceController? get voice;
  static Future<AppServices> open(Backend b) => switch (b) {
    Backend.matrix => MatrixServices.open(),
    Backend.mock   => MockServices.open(),
  };
}
```

`main` then reads: `final services = await AppServices.open(Backend.fromEnvironment());`
and `runApp(LoafApp(services))`. No branch survives in `main`.

**2.2 Mutable globals.** `appearance`, `notifications`, `session` (`late final`),
`noticeRoutes`, `voice`, `newRooms`, `updater` (nullable top-level vars) are set in
`main` and read in `LoafApp.build`. They should be constructor fields of `LoafApp`
(i.e. the `AppServices` above). `late final` globals turn ordering mistakes into
runtime `LateInitializationError`s.

**2.3 Theme by ternary.**
```dart
final nihon = appearance.effective == LoafThemeId.nihon;
theme: nihon ? loafNihonTheme() : loafLightTheme(),
darkTheme: nihon ? loafNihonTheme() : loafDarkTheme(),
```
…while `loafTheme(LoafThemeId)` already exists in `loaf_theme.dart:512` and `main`
doesn't use it. Two sources of truth: `LoafThemeId` and a separate global
`themeMode` flipped by a debug-only Ctrl+T. Give the id its palette pair:

```dart
enum LoafThemeId {
  loafDark('Loaf Dark', light: _lightTokens, dark: _darkTokens),
  nihon('日本', light: _nihonTokens, dark: _nihonTokens);
  ThemeData get light => _theme(lightTokens, Brightness.light);
  ThemeData get dark  => _theme(darkTokens, Brightness.dark);
}
// main: theme: id.light, darkTheme: id.dark
```

and make the Ctrl+T palette flip part of `AppearanceController` (or a debug-only
wrapper), not a production global.

**2.4 Platform checks.** `defaultTargetPlatform == TargetPlatform.macOS ? SystemAudioDevices() : null`,
`Platform.isLinux || Platform.isMacOS` for signals, `hasCalls`, `isDesktop` —
these belong in a single `HostPlatform` value (built once from
`defaultTargetPlatform`) that *returns* the audio-device source, signal handling
and capabilities. `lib/ui/platform.dart` already has 9 such checks; it's the
natural home.

## 3. `lib/update/`

**3.1 Organise by platform.** Today everything sits flat and it's unclear what
runs where:

```
lib/update/
  updater.dart            (move from lib/ui/model/updater.dart — it's not UI)
  state_updater.dart
  pick_updater.dart
  feed/      release_feed.dart, ed25519.dart, asset_download.dart, build_info.dart
  macos/     sparkle_updater.dart
  linux/     appimage_updater.dart, flatpak_updater.dart, flatpak_portal.dart, dbus_flatpak_portal.dart
  windows/   windows_updater.dart, bundle_swap.dart
```

`FakeUpdater` lives in production code (`lib/ui/model/updater.dart`) — move it to
`lib/ui/mock/` (it's used by the mock backend) or `test/`.

**3.2 AppImage and Windows updaters are one class written twice.** Identical:
`_timers`, `start` scheduling, `_checking` dedupe, `check()` guard, `restart()`,
`dispose()`, `_launchDetached`, `_exit`, the fetch→verify→size-check prelude.
Extract a `SelfUpdater extends StateUpdater` that owns all of that and asks the
subclass for one thing: `Future<void> install(VerifiedAsset asset)`. Inject one
`Host` collaborator (`launch`, `quit`, `FileSystem`, `http.Client`) instead of
four nullable parameters.

**3.3 Make "verified" a type.** Today any `ReleaseAsset` can be downloaded;
verification is a boolean check the caller must remember. Instead:

```dart
final class VerifiedAsset {
  VerifiedAsset._(this.asset, this.release);
  static VerifiedAsset? check(Release r, AssetKind kind, SignatureCheck verify) { ... }
}
Future<File> download(VerifiedAsset a, ...);   // won't accept an unverified asset
```

The `asset.size > largestAsset` and signature checks move into `check`, and
`_check` shrinks to ~10 lines.

**3.4 `_check` guard duplicates `StateUpdater._outcome`.**
`state is UpdateReady || state is UpdateApplying` re-derives what `_outcome`
already knows. Use one method on the sealed state (`bool get staged`).

**3.5 `UpdateReady.version` / `UpdateApplying.version` are `String?`**, and the
shell encodes "no version" as `''` in `_laterUpdate`. Make it a type:
`sealed class ReleaseName { Known(String) ; Unknown }`, or have Sparkle always
report one.

**3.6 `restart()` "only means anything in `UpdateReady`"** and silently returns
otherwise. Put the action on the state: `UpdateReady.restart()` — then you can't
call it from the wrong state.

**3.7 `asset_download.dart`.**
- It's ~95% HTTP mechanics (status, Content-Length, streaming with idle timeout,
  byte cap, fsync, hash). That's a generic `HttpDownload` utility
  (`download(uri, to, {expectedSize, sha256, idleTimeout})`), not updater code.
  `lib/matrix/loaf_http_client.dart` is a second HTTP wrapper; the two should be
  one module.
- Leaves `to` partial or garbage on failure and documents that as the caller's
  problem. The function should own the temp file: write to a temp it creates,
  verify, then return the `File`; on any failure, delete it. Callers can then
  never observe a half-written file.
- Two `try/catch` blocks around `flush`/`close` log and swallow — an error closing
  the sink is a failed download; let it throw.
- The fsync (`open(mode: append)` + `flush`) is right but belongs in the
  atomic-write utility (§6.2).

**3.8 `bundle_swap.dart`.**
- The `executable` comment ("What every build has, and what goes in last and
  comes out last, so the shortcut points at nothing for as short a time as
  possible") — rewrite as one plain sentence about *why*: "Swapped last so the
  Start-menu shortcut is broken for the shortest time."
- `_files`, `_at`, `_join`, `_swappable` hand-roll path handling with
  `Platform.pathSeparator`, `substring(dir.path.length + 1)` and `replaceAll`.
  `package:path` (already in the lockfile) does all of it: `p.join`,
  `p.relative(entity.path, from: dir.path)`, `p.split(rel).first`,
  `p.posix`/`p.windows` contexts. Declare it as a direct dependency.
- The journal is a tab-separated text format parsed with `indexOf('\t')` and
  string `case 'new'/'old'`. Make the line a type:
  `sealed class JournalEntry { SetAside(rel); PutInPlace(rel); static JournalEntry? parse(String) }`.
- `_retrying` / `_renameFile` — see §0.
- Long chained expressions (`_files`, `_executableLast`) read better as a
  `RelativePath` type with `isExecutable`, `isSetupFile`, `isSetAside` getters.

**3.9 Stringly Sparkle channel.** `'upToDate'`, `'found'`, `'preparing'`,
`'ready'`, `args['version'] as String?`. See §7 (Pigeon).

## 4. Domain types — the generic-`Event` problem

**4.1 `MatrixTimeline._message` (matrix_timeline.dart:256–335).** An 80-line
function that takes the SDK's generic `Event`, branches on `event.type` strings,
`relationshipType`, a `_fileTypes` set, `media == null`, `linked != null`, and
assembles a flat `ui.Message`. This is exactly the case you described. Introduce
a validated layer:

```dart
sealed class TimelineEvent {
  static TimelineEvent? from(Event e) => switch (e) {
    _ when e.redacted => null,
    _ when e.relationshipType case RelationshipTypes.edit || RelationshipTypes.reaction => null,
    _ when e.type == EventTypes.Encrypted => LockedEvent(e),
    _ when e.type == EventTypes.Sticker || _fileTypes.contains(e.messageType) => MediaEvent(e),
    _ when e.messageType == MessageTypes.Emote => EmoteEvent(e),
    _ when e.type == EventTypes.Message => TextEvent(e),
    _ => null,
  };
}
```

Each subtype exposes only what it has (`MediaEvent.media`, `TextEvent.html`,
`LockedEvent` has no body) and maps itself to the UI type. The same
`TimelineEvent.from` should feed `unread_rules.dart`, `matrix_arrivals.dart` and
notifications, which each re-derive "is this a message?" from raw `type`
strings today (56 raw `.type ==` / `content[...]` sites across 13 files).

**4.2 `ui.Message` is a bag of optionals.**
`locked` + empty `body`; `media` *or* `callLine` *or* text; `uploaded` "set only
while sending"; `stub` with a fake `DateTime.utc(1970)`. Representable nonsense:
a locked message with media; a stub with reactions; `uploaded: 0.5` with
`status: sent`. Shape it:

```dart
sealed class MessageContent { }
final class TextContent  extends MessageContent { String body; String? html; Uri? previewLink; }
final class MediaContent extends MessageContent { Media media; String caption; }
final class LockedContent extends MessageContent { }
final class CallLineContent extends MessageContent { CallLine line; String label; }

sealed class Delivery { Sent(); Sending(double? uploaded); Failed(); }

class Message { id, author, sentAt, MessageContent content, Delivery delivery, reactions, edited, Quote? replyTo }
sealed class Quote { LoadedQuote(Message); MissingQuote(id, author) }   // replaces Message.stub
```

`groupTimeline`'s `message.callLine != null` becomes a type test.

**4.3 `Channel` is four types in one.** `members` (DM/room only), `waitingFor`
and `earlier` (DM only), `occupants`, `silenced`, `canSilence` (voice only),
`kind` deciding which apply. `MatrixRooms._channel` builds it with a nested
ternary for `kind` and `kind == voice ? … : const []` per field. Make it
`sealed class Channel` with `TextChannel`, `VoiceChannel`, `DirectChat`, `Room`
subtypes, and let `MatrixRooms` construct the right one from the `Room`.

**4.4 `Invite` has `kind` + nullable `room` + nullable `space`.** Nothing stops
`kind: space, room: x, space: null`. `sealed class Invite { DirectInvite(Channel); RoomInvite(Channel); SpaceInvite(Space) }`.

**4.5 `LoafSession`.** `AccountState` enum plus `softLogout?`, `trust`,
`incoming?` that only mean something in some account states.
`sealed class Account { SignedOut(); SoftLoggedOut(SoftLogout); SignedIn(DeviceTrust trust, IncomingRequest? incoming) }`.
And `consumeFailure()` — a debug lever — is on the production interface.

**4.6 `Rooms` + `Set<RoomAbility>`.** Callers check `_can(RoomAbility.kick)`
before calling `kick`, which exists either way. Capabilities should be presence
of a typed sub-object (the codebase already does this for `Calls? calls`):
`Moderation? moderation`, `Invites? invites`, etc. A missing capability is then
a `null` the type system makes you handle, not a runtime set lookup.

**4.7 Sentinels instead of types.**
- `Member.copyWith(statusMessage: '')` means "clear", `null` means "keep".
- `_answering ?? ('', null)` in `AppShell._buildMain`.
- `_laterUpdate` uses `''` for "no version".
- `mockHome.id` doubles as the "Home" place id in production (`_placeId`, ~12
  sites). Make `sealed class Place { Home(); InSpace(String id) }`.

**4.8 Untyped persistence.** `unread_tally.dart` and `matrix_unread.dart`
parse positional JSON arrays with `json[0]! as String`, `r[1] as int`,
`json.length > 3 && json[3] is String ? …`. Use the `release_feed.dart` style:
a `switch (json) { [String id, int ts, ...] => …, _ => throw FormatException }`
pattern per type.

  computed once, then one `switch` renders it. Extract a `ShellController`

  `wide ? a : b` layout split — a `ShellLayout` sealed type (`Wide`/`Narrow`)

## 6. Generic tools buried in domain code

**6.1 Paths built by string concatenation — 18 sites.** `'${dir.path}${Platform.pathSeparator}name'`
in `client_factory.dart`, `media_store.dart`, `matrix_rooms.dart`,
`pick_notifications.dart`, `pick_updater.dart`, `windows_updater.dart`, the three
settings stores, and `bundle_swap.dart`. `media_store.dart:159` re-implements
`basename` with `lastIndexOf(pathSeparator)`. Use `package:path` everywhere.

**6.2 Atomic write ("write beside, rename over") — three hand-rolled copies**
(`appimage_updater.dart`, `matrix_rooms.dart:133`, `media_store.dart:405`) — and
the settings stores *don't* use it, so a crash mid-save truncates
`appearance.json`. One `writeAtomically(File, bytes)` in `lib/util/fs.dart`.

**6.3 Three copy-pasted settings stores.** `Memory/FileAppearanceStore`,
`Memory/FileNotificationStore`, `Memory/FileVoiceStore` — six classes, same
body, differing only in file name and `fromJson`. One generic:

```dart
abstract interface class Store<T> { Future<T?> load(); Future<void> save(T value); }
class JsonFileStore<T> implements Store<T> {
  JsonFileStore(this.file, {required this.decode, required this.encode});
}
class MemoryStore<T> implements Store<T> { ... }
```

**6.4 Image sniffing in `MatrixRooms`.** `imageExtension(Uint8List)` (magic
bytes for PNG/JPEG/GIF/WebP) is a static on the rooms class.
`package:mime`'s `lookupMimeType('', headerBytes: b)` + `extensionFromMime` does
this and is already in the lockfile. The surrounding notification-avatar
caching (`matrix_rooms.dart:110–145`) belongs in the notify layer, not rooms.

**6.5 Retry loop** — §0. **HTTP download** — §3.7.

**6.6 42 catch-all swallows** (`catch (_) {}`, `on Object {`), worst in
`matrix_rooms.dart` (7), `devices_section.dart` (3), `matrix_timeline.dart` (3).
Each should catch the specific exception it expects, or return a `Result`-like
sealed type the caller must handle. `MatrixTimeline._open` turns *every* error
into `timeline = null` and then infers what happened from `at != null`.

## 7. Platform channels (Dart ↔ Swift)

- `LoafMediaPlugin.swift` dispatches 14 string method names and decodes
  `[String: Any]` with `as?` per argument; the Dart side mirrors it by hand.
  `SparkleUpdater` does the same with string states.
- `StreamProgress` carries `complete: Bool` and `failed: Bool` — both `true`
  is representable. Make it an enum (`receiving(received,total)`, `complete`, `failed`).
- **Pigeon** generates typed Dart + Swift for both ends from one Dart schema;
  the hand-written decoding disappears. (Its Windows/Linux output is C++, which
  isn't needed — those platforms already use Rust FFI. Swift-only use stays
  within Dart/Rust/Swift.)

## 8. Rust (`loaf_notify`, `loaf_media/*/rust`, `loaf_streams`, `tool/chime`)

The healthiest part of the tree: no `unwrap()` outside tests, every FFI entry
point is panic-guarded, `// SAFETY:` comments are present. Small items:

- FFI status codes are loose `const i32`s (`OK`, `PANICKED`, `BAD_STRING`, …).
  A `#[repr(i32)] enum Status` keeps the C ABI and makes `match` exhaustive;
  mirror it as a Dart `enum` with a `fromCode` constructor so Dart stops
  comparing raw ints.
- `string()` returns `Result<&str, i32>` — use the `Status` enum as the error
  type.

## 9. Suggested order

1. **CI → mise tasks** (§1). Self-contained, quick, removes the `sed`.
2. **Utilities module** (§6.1–6.4 + retry + download): `package:path`,
   `writeAtomically`, `Store<T>`, `HttpDownload`, `retry`. Unblocks 3 and 5.
3. **`lib/update/` restructure** (§3): folders, `SelfUpdater`, `VerifiedAsset`,
   `package:file`, typed journal.
4. **`AppServices` + theme pair** (§2): kills every backend check and the
   mock fallbacks in `AppShell`.
5. **Domain types** (§4): `TimelineEvent` → `Message`/`Quote`/`Delivery` →
   sealed `Channel`/`Invite`/`Account`. Largest; touches most widgets and tests.
6. **`AppShell` split** (§5) once 4 and 5 have removed the mock branches.
7. **Pigeon** (§7) and the Rust `Status` enum (§8).
